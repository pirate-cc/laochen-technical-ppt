# Skill revision and paired deck evaluation

仅用于有实质影响的 Skill 修订或明确要求的前后比较，不给普通 PPT 制作增加跨场景测试。按受影响行为选择下列检查；涉及版式/动态效果时再做同输入实际出片。成稿沿用 [制作核对](implementation-and-checks.md#minimum-production-confirmation)，可视例子见 [案例](visual-cases.md)。

## Skill revision checks

- 选择少量不同目的的实际任务，例如陌生题材讲解、操作培训、给定数据阅读稿、已有 PPT 局部修改；题材不必来自 Skill 示例。明确输出格式、应用、模板、讲演/静态用途，适用时包含未给模板但授权自行设计的任务。
- 给独立执行者真实请求、候选 Skill 和必要原材料，不预告答案、本轮怀疑点或强塞指定来源。仅文案/素材任务检查相应交付；文件编辑用隔离副本。观察材料使用、来源适配/可追溯性、事实状态、编辑粒度、视觉/动态关系及范围外内容保留，不能用关键词命中替代判断。
- 内容深度变化：用材料充分的同页比较、方法操作或已有结果页检查解释是否完整，再用资料有限/局部修改检查是否过度补写。比较或跨页论证变化：选不同输出对象、部分达标结果或配置/日志材料，检查可比范围、证据对应和关系组织。不得补造结果或以字数、公式数、动画数判定通过。
- 标题变化：检查不同页面目的，并夹入已有自然标题及真实操作顺序；改写应具体、证据范围不变、正文不被顺带删改，不按禁词、字数或与示例逐字一致评分。
- 分别保留请求/材料、实际交付和判断依据。格式、链接及安装一致性只证明结构；文案/分镜检查不是 PPT 渲染、编辑或播放验证。工具失败、材料缺口及未完成项如实记录。修复已暴露问题后只复验受影响行为，有限场景成功不代表所有主题/工具均通过。

以下用于两版实际成稿比较；无需为纯结构整理强行制作两套 PPT。

## Freeze comparable inputs

修改前保存旧 Skill 和可复核版本标识，固定原始材料、请求、页数、模板/视觉约束、讲演或阅读用途、目标应用、生成工具及约定编辑粒度。输入文件可记录哈希；哈希只能证明输入一致，不证明输出质量。保持模型与执行条件可比，实际差异如实记录。

若已有满足共同条件的真实基线，可直接保留；重新制作时让旧版和候选版各自正常完成制作、渲染、自查与必要修复，不故意弱化旧版，也不让新版获得额外资料或人工精修预算。无法复原旧环境时称为受控重建，不冒称历史原稿。

## Keep the comparison independent

具备独立代理条件时，给两个执行者相同请求、原材料与必要工具说明，各自只读对应 Skill 和隔离输出目录；不传递预期答案、另一份稿、怀疑点或预设优劣。评审者先看匿名编号的实际页面和共同材料，再核对版本。没有独立执行条件时说明同一作者、上下文或顺序可能影响结果。

选择能暴露本次规则差异的少量材料，同时包含不能以删内容解决的复杂页。可覆盖工程连接、公式/方案比较、研究结果与经营数据；不强制每次凑齐场景。教学构造要标明身份。用于讲解新规则的案例与用于检验迁移的材料应分开；已公开的测试案例后续只能算回归样例，不能再当未见材料。

## Inspect actual outputs

从两份保存后的 PPTX 导出同尺寸渲染，逐页全尺寸查看；拼图只帮助看整套一致性，不代替逐页查看。涉及原生动态时实际播放相关入场、中间与终态，分别保存配置与效果证据。对象检查、渲染、播放和编辑试验的完成层级分开记录。

| 比较项 | 可复核的判断 | 不采用的替代指标 |
| --- | --- | --- |
| 内容与证据 | 对照原材料核查必要事实、条件、单位、公式、比较范围和结论；缺失在哪一页哪个对象 | 字数、公式数、标题包含关键词 |
| 布局与关系 | 能否找到对应对象和共同基准；路径是否连续，标注是否靠近证据，主次与阅读顺序是否清楚 | 版式种类越多越好、卡片越少越好 |
| 可读性 | 在共同渲染尺寸下核对截断、碎行、坐标、图例、公式和对比；给出具体位置 | 仅凭文本框边界或脚本无报错 |
| 一致性 | 同角色样式和同对象身份是否稳定；例外是否服务页面任务 | 全页所有字号或所有颜色都相同 |
| 原生编辑与动态 | 检查必要对象与数据；实际播放看同步、保留上下文和中间遮挡 | 文件有 chart、timing 元素或动画数更多 |

用具体前后页面、对象及观察说明改善、退步或无明确差异。不以综合审美分数或单次样例宣称普遍提高；如果新版未改善，就按实际结果收窄结论或修正规则。工具运行速度也不能单独代表设计质量。

## Repair and retain useful evidence

比较最终成稿质量时使用两版正常自查后的合格稿。若还要判断规则遵循率或修复成本，另保留首次完成稿，分别记录初始问题、修复原因/轮次和最终效果；不能用筛选后的合格稿声称首次遵循率提高。真实问题由相应制作方修复并重渲染受影响页，两版机会相同，不为预期胜负无限调稿。必要验收完成即停止。

在现有任务目录保留复现所需的输入、版本、实际输出、判断依据；实际出片比较包括两份 PPTX、必要源文件和渲染/播放证据。清理一次性临时副本，不为每页建立管理系统。若将案例收入 Skill，只打包公开许可或自制合成材料，移除私人路径、项目数据和凭据，并说明实际验证环境。可视案例应包含修改理由和适用边界，案例布局与数字不是其他任务的默认答案。
