# Worked examples

下面的产品、界面和数字均为明确给出的教学设定，可据此构造示意对象；不代表真实产品功能、项目记录或新运行结果。它们演示“场景 → 解释任务 → 素材与对象 → 动态”的推导。用于真实任务时，所有事实、素材身份、视觉风格和分镜都由本次来源确定。

## Task boundary cases

| 请求 | 本次工作与可观察结果 |
| --- | --- |
| “检查第 3–5 页的讲解逻辑和文案，告诉我哪里可以改。” | 阅读目标页及必要上下文，报告位置、依据与建议，原稿不变。 |
| “检查并修复第 4 页的动画问题，其他页面保持原样。” | 检查并修复受影响对象和效果，复查用户要求的相关部分；配置与实际播放证据分别报告。 |
| “只把第 2 页标题改成指定文字，其余不动。” | 替换该标题文字，保留格式、对象身份和效果引用，确认保存结果；不改其他页或重新选材。 |
| “第 5 页换成提供的新截图，保留文字和动画，我自己检查。” | 检查新图，替换目标图像并保留适当裁切和效果身份；对象 ID 改变时修正受影响引用。 |
| “沿用模板做 12 页讲演 PPT，做完交给我自行检查。” | 交付一个 12 页可编辑稿，全部页面含服务内容的原生动态，并完成最小制作核对。 |
| “做 8 页静态阅读版，图表数据可编辑。” | 以完整静态状态和足够可见说明交付，保留图表数据关系。 |
| “没有模板，你根据材料自行设计，输出本地 PPTX。” | 在实际工具允许的流程内确定统一视觉方向，按指定目标制作；不新增大纲或样稿审批。 |
| “更新这个云端演示里的两页。” | 在已有目标及授权范围内编辑，保留无关页面；不另造本地或其他云端副本。 |
| “只给一张主题背景和提示词。” | 仅交所需图片和提示词；素材的题材、构图与风格由本次要求决定。 |

这些是范围判断示例。具体检查与交付统一使用 [制作边界](implementation-and-checks.md#when-to-use-checks) 和 [最小制作核对](implementation-and-checks.md#minimum-production-confirmation)，不由案例新增审批、渲染、播放或排练要求。

## Story and pacing

先选择观众需要的理解路径，再决定页数分配和布局。下面展示不同目的下可采用的组织方式：

| 场景 | 可选顺序 | 选择理由 |
| --- | --- | --- |
| 向新用户介绍一个产品 | 使用情境 → 整体与关键特征 → 对应操作或结构 | 先使对象有意义，再解释值得注意的部分。 |
| 给熟悉产品的人员培训一项操作 | 任务与起始状态 → 操作与反馈 → 完成状态 | 省略已有基础，沿实际操作建立可执行理解。 |
| 用已有数据支持工作讨论 | 当前问题 → 可比数据及差异 → 依据支持的解释或选项 | 围绕实际讨论目的安排证据，避免无关背景。 |
| 介绍作品或历史发展 | 作品/人物身份 → 关键材料 → 时间、空间或主题联系 | 让每一段叙述有对应材料，按理解需要选择叙事线索。 |

实际任务可采用其他顺序，也可组合这些关系。讲解一个细节、完成一次比较和执行一段操作所需时间不同，不按页数平均分配时长。规划在内部完成；需要的前置定义、证据身份和转折在对应位置出现。

## Product introduction with editable motion

**教学场景：** 向新用户介绍一盏虚构的折叠台灯。已知且仅使用这些设定：底座支撑灯体；灯臂通过转轴与底座连接；灯头位于灯臂末端；按钮按次序切换三个亮度档位。转动范围、功率、尺寸及具体商品外观未定义。图形标为“台灯结构示意”。

**本页目标：** 让观众理解支撑、转动和控制分别由哪些部件承担。

**标题：** 台灯的支撑、转动与亮度控制

**可见成稿：**

> 底座支撑灯体，灯臂通过转轴连接到底座。转动灯臂时，灯头随灯臂改变位置。
>
> 按钮用于依次切换三个亮度档位，灯臂的位置调整和亮度切换由不同部件完成。

**素材与构图：** 依据上述关系画一幅原生示意图：底座、灯臂、灯头、转轴和按钮各有独立对象；标签贴近对应部件。组件比例只用于教学，不写成产品尺寸。若真实任务提供产品照片，先核对实际外观与转轴位置；需要解释部件运动时仍准备相应独立对象或可靠结构图，不能把整张照片当作可拆分结构。

| 对象与阶段 | 原生动作 | 保留上下文 |
| --- | --- | --- |
| 入场：完整示意图与必要身份标签 | 一次协调入场，或者初始显示后由下列内容阶段承担动态 | 所有部件的整体关系。 |
| 解释转动：转轴标识、灯臂与灯头、第一段说明 | 同次点击显示说明和转轴标识，让灯臂与灯头绕示意转轴作短程协同转动 | 底座固定，转轴位置稳定；动作结束后保持可读状态。 |
| 解释控制：按钮标识、三个状态标签与第二段说明 | 下一次点击强调按钮，并按三个离散档位依次切换状态标记 | 保留结构和第一段关系，不用亮度数值暗示未定义性能。 |

在选择素材前就确定转轴、灯臂和灯头的运动依赖。若所用 API 的对象旋转中心不能直接表达转轴，使用适当分组或路径构造，经配置核对确认运动目标；只淡入标签不能实现本页的转动解释。颜色和背景按实际模板或已确定的视觉方向设置。

## Procedure training with native interface states

**教学场景与完整规则：** 一个虚构的报销表单含“金额”“用途”“提交”三个控件。金额必须大于 0，用途必须非空；不满足时保留“草稿”状态并提示相应字段，满足后点击“提交”进入“已提交”。本例不包含审核、到账或其他后续流程。

**本页目标：** 让初次使用者知道应填写什么，以及怎样确认提交完成。

**标题：** 填写金额和用途，再提交申请

**可见成稿：**

> 填入大于 0 的金额，并说明用途。缺少任一项时，表单会提示对应字段，申请仍为草稿。
>
> 两项填写完整后，点击“提交”。状态变为“已提交”，表示本次提交操作完成。

**素材与构图：** 用原生文本框和按钮画清楚标注为“教学界面”的表单。示例输入为金额 120、用途“办公用品”。不把示意界面写成真实软件截图。真实培训任务使用实际版本界面与操作规则，再决定是否需要局部裁切、不同状态截图或原生标注。

| 阶段 | 动作与说明 | 保留内容 |
| --- | --- | --- |
| 初始状态 | 显示空表单、“草稿”和标题 | 控件位置保持稳定。 |
| 填写 | 依次突出金额与用途，同步出现填写值和对应说明 | 已完成字段继续可见。 |
| 提交与反馈 | 强调“提交”，随后将状态替换为“已提交”，同步出现第二段说明 | 保留填写值，给观众稳定的结束状态。 |

点击分组由讲解需要决定；本例不要求每个字段各点一次。只有需要教学错误处理时才展开错误状态，使用上述完整规则即可，不增加无依据的审核过程。

## Comparison with supplied data

**完整教学数据：** 某虚构业务的两类产品销量，单位为件。数据仅用于说明比较，不代表任何公司实绩。

| 类别 | 上期 | 本期 |
| --- | ---: | ---: |
| A 类 | 300 | 360 |
| B 类 | 200 | 180 |
| 合计 | 500 | 540 |

**本页目标：** 解释总量变化及两类产品的贡献，不推断变化原因。

**标题：** 总销量增长 8%，A 类增加抵消了 B 类下降

**可见成稿：**

> 总销量由 500 件增至 540 件，增加 40 件，增长 8%。A 类增加 60 件，B 类减少 20 件，二者合计形成净增加。

**素材与构图：** 用同一口径的原生分组柱状图或清楚的差异图。图表数据来自上表，保留类别、期间和单位；没有理由再找背景照片。计算为 (540−500)/500=8%，60−20=40。不能把数据变化写成促销或产品改进的因果效果。

**讲演动态：** 先保留期间、坐标和比较对象，再随说明突出 A 类的增加、B 类的减少，最后关联到总量。已讲对象留在图中供比较；效果操作实际系列或标注，不补造两期之间的观测值。阅读版直接显示完整比较和解释。

## Complete one-slide rewrite

**完整教学设定：** 采样点序号 n=[0,1,2,3]，输入 x=[2,2,4,8]。普通最小二乘直线为 x̂[n]=2n+1，拟合值为 [1,3,5,7]；逐点相减得到 y=[1,−1,−1,1]。这是“线性去趋势算例”，不是现场测量。

原稿“去趋势，改善数据质量”没有解释具体操作。对能读坐标并理解算术的听众，选择输入点 → 拟合线 → 逐点相减 → 差值含义的讲解顺序。

**标题：** 线性去趋势：拟合直线，再逐点相减

**可见成稿：**

> 在 n=0、1、2、3 四个采样点上，原始序列为 [2,2,4,8]。对它作直线拟合，得到 x̂[n]=2n+1，对应拟合值 [1,3,5,7]。
>
> 将原始序列与拟合值逐点相减，得到 [1,−1,−1,1]。这个差值序列表示原始数据相对拟合直线的起伏。

**主图与动态：** 用原生坐标、点、拟合线、公式与差值展示运算。轴名为“采样点序号”和“幅值（任意单位）”。先呈现输入，随后让拟合线及其解释同步出现，再呈现相减操作、差值和第二段说明，保留前面的数量供核对。

**备注示例：** 第一个点是 2−1=1，第二个点是 2−3=−1，其余点采用相同规则。备注补充讲解节奏，可见文字本身已说明运算与输出。

这个算例只说明一种方法页的展开方式。其他题材从其实际操作或关系出发；不要求每页都有公式、数值算例或输入输出链。

## Conceptual scene with separate layers

**教学任务：** 介绍一个拟议维修服务流程“接收物品 → 检修 → 归还”。这是流程概念，不是某个真实门店的运行记录。需要环境氛围时，可用合适实景参考或生成一幅维修工作室插画；关系与节点仍由上述流程给出。

**素材需求先行：** 环境背景提供场所感，三个流程节点、方向箭头和说明保留为原生对象。若需要移动“物品”来解释传递，单独准备该物品对象，背景中不画死它或流程箭头。

**可改写的生图示例：** “为一页维修服务流程说明生成工作室环境插画：桌面和工具集中在画面左下，右侧留出连续的清晰空间给流程图；不含人物、文字、标志或步骤箭头。” 实际生成前，将风格、画幅、色调和留白位置按本次模板或视觉方向写入提示词；此例的位置不是通用布局要求。

主图说明可写“物品先被接收，随后进入检修，完成后归还”。讲演时按流程显示下游节点、连接和说明；若采用物品移动，先让目的地可见，再沿已显示路径移动。背景提供情境，节点与动作承担解释。

## Natural Chinese

| 草稿 | 可直接使用的改写 | 改进依据 |
| --- | --- | --- |
| “结构赋能多元体验。” | “灯臂绕转轴改变灯头位置，按钮用于切换亮度档位。” | 写出实际部件和作用。 |
| “提交操作实现流程闭环。” | “点击‘提交’后，状态变为‘已提交’，表示本次提交操作完成。” | 说明操作与可观察反馈。 |
| “经营表现获得全面提升。” | “总销量增加 40 件；A 类增加 60 件，B 类减少 20 件。” | 保留有依据的差异，避免夸大。 |
| “去趋势，改善数据质量。” | “拟合一条直线，再从原序列逐点减去拟合值，得到差值序列。” | 将名称展开为操作。 |

这些改写只使用前述教学设定。用于真实产品、界面和业务时，换成本次材料支持的名称、功能、状态和数字。它们展示自然表达的判断方式，不是固定句式或禁词表。

## Title without a presenter cue

若标题是“两个方案的适用条件”，正文已完整比较，则小字“先看各自特点，再作选择”只是讲述顺序，可放备注。明确比较范围或条件的副标题仍有用，例如“同一预算与交付期限下的比较”。按信息作用决定保留，而不是一律删除副标题。

## Auxiliary small text below an example

操作示例下的“大家可以实际试一试”通常属于口头提示。若页面正在组织课堂练习，“使用所给数据计算两期增长率”就是实际任务内容，应放入可读正文。图旁标签、单位、条件和必要署名始终按其解释作用处理。

## Live and reading versions

沿用前述销量表，讲演版可以在相同图中逐项强调 A、B 类变化，旁边保留完整的关键解释；备注帮助讲述节奏。阅读版直接显示完整图与“60−20=40”的贡献关系，使读者无需点击也能理解。

两种用途均使用真实任务中自己的数据与条件。只制作用户要求的版本；正文密度由所需解释和阅读方式决定，不设固定字数。

## Accurate delivery wording

常规制作可写“已完成可编辑 PPT，已写入原生点击动画”，并给出实际文件路径。仅对实际写入的功能作此说明，不从脚本完成推断播放通过。用户要求播放检查而未能完成时，明确报告受影响的检查与恢复条件。交付边界详见 [交付规则](implementation-and-checks.md#delivery-and-optional-review)。

## Skill revision checks

本节用于有实质影响的 Skill 修订，按改动选择少量任务检查行为；它不要求每份 PPT 都新增测试或播放。主文件格式、链接和安装一致性检查只能证明相应结构，不能证明跨场景选材和表达质量。

- 选择不同的实际任务目的，例如陌生题材的素材与讲解、操作培训、基于给定数据的阅读稿，以及既有 PPT 的局部修改；题材不必来自本文件。
- 给独立执行者真实请求、候选 Skill 和完成任务所需的最少原材料，不提前给预期答案、指定来源或本轮怀疑点。仅文案/素材任务检查其实际交付；文件编辑任务用隔离副本。
- 看可观察结果：是否读取和正确使用材料，是否取得可追溯的合适来源，是否遵守事实与编辑粒度，是否选择服务讲解的视觉/动态，以及是否保留范围外内容。不能用关键词命中代替这些判断。
- 格式、目标、模板和静态/讲演用途按测试请求明确，必要时增加一个未给模板但授权自行设计的任务。工具失败或资料缺口按实际影响记录，不把未完成任务记为通过。
- 对已经暴露的问题作针对性修订，再检查受影响行为。沿用项目现有记录保存请求、材料定位、实际输出和结论；只保留复现仍需要的材料，清理一次性临时副本。有限场景的成功不等于所有主题与工具都已验证。
