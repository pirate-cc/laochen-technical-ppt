# 协作与交接

启用专项子代理时读取本文件。所有角色遵守 [任务范围](../SKILL.md#task-scope) 和 [检查边界](implementation-and-checks.md#when-to-use-checks)；本文件只定义分工、交接与文件所有权。

## Task selection

- **主代理单做：** 已有故事、模板和实现清楚，任务是局部修改；或整套内容简单、素材可用、动态常规，委派成本大于可拆出的工作量。
- **主代理 + 必要专项组合：** 从 A 内容与证据、B 视觉与素材、C 制作与动态中选择有独立工作量的角色，允许一个、两个或三个专项。A+B 适合需要整理证据与定制素材、制作常规的任务；A+C 适合内容与原生动态复杂、现成素材足够的任务；B+C 适合文案已定、素材与动态复杂的任务；三类均需要时启用 A/B/C。未派出的职责由主代理承担，用户明确指定协作时服从其范围。

使用现有子代理能力，沿用用户的模型设置，不创建用户侧新聊天。保持一个主代理和最多三个专项角色；专项不再自行委派。并发不足时等待依赖、复用或顺序调用现有专项；工具不可用时由主代理承担相同职责，保留单稿所有权并继续制作。未实际启动的角色不能写成已启动。

先在交接中标明动作范围。审阅专项只检查和回报，制作角色名称不赋予修改授权；仅素材或文案任务也不启用 PPTX 写入。相关例子见 [任务边界](worked-examples.md#task-boundary-cases)。

## Shared brief

主代理先读取用户请求、已有成果与相关原材料，复用已有工作笔记、计划或交接消息。全局只写一次：动作与受影响范围、题材与听众、希望观众理解或完成什么、讲演/阅读方式、总页数或时长、目标应用与输出目的地、模板代表页或已确定的视觉方向、必须保留项、来源限制、权威输出路径、当前写入方和交付/检查方式。沿用主规则的成稿与动态标准，记录用户明确的静态用途或复查要求。来源位置以实际文件/图号/数据定位为准，不仅传递主代理的结论。

只为本次创建或重做的页面补齐逐页信息；讲演页给出动态安排，简单页一句话即可。局部任务保留既有安排，只记录受影响对象及必要依赖；静态用途无需动画参数：

| 信息组 | 最少内容 | 主要贡献方 |
| --- | --- | --- |
| 页内容 | 稳定页标识、当前顺序、本页主体、标题与完整解释、前后页依赖；早期标明初稿与待素材确认的具体内容，制作前形成可直接上屏的文案 | 主代理和 A |
| 依据与语义 | 文案所指的具体对象、来源位置、候选/示意/设计/实测等状态，以及必要单位、定义和条件 | A |
| 视觉与素材 | 主构图、素材承担的解释任务、项目内路径、必要原来源/署名或生成提示词、裁切与分层、必须原生编辑的部分 | B |
| 动态与对象 | 入场状态、各次点击的目标/动作/关联说明、保留上下文及稳定终态；C 再确定稳定对象名、效果、触发、顺序与时长 | B 提出视觉分镜，C 负责可实施的分镜和实现 |

只有真实缺口才记录“受影响页、问题、接手人和继续所需条件”。不强制另建 JSON、清单系统、角色目录或管理报告。

## Roles and reference loading

**主代理：统筹与交付。** 在授权范围内决定讲解顺序、页数和模板语言，维护统一页级安排；统一标题、正文的语气与术语，衔接内容、视觉和动态，由当前写入方制作。需要改变页序、技术口径、模板或可编辑边界时由主代理处理。新建或整体重做可读 [讲解顺序示例](worked-examples.md#story-and-pacing)；局部任务只读取目标对象所需参考。

**A：内容与证据。** 读取分配的原材料，以及 [内容写法](research-explanation.md#writing-from-sources)、[中文成稿](research-explanation.md#natural-chinese-technical-copy)、[页面角色](research-explanation.md#substance-by-page-role) 和需要的文案示例。先交有依据的初稿与具体素材需求，根据 B 找到的实际材料修订，再交已通读、可直接上屏的标题与逐页解释，附来源定位、事实状态、图中目标与页间依赖；不只交关键词、抽象概括或留给用户扩写的提纲。A 可建议内容调整，不能自行改变最终页数或将教学/历史数据当作本次运行；不另做 PPTX。

**B：视觉与素材。** 读取模板或视觉方向、页目标和文案初稿，以及 [视觉/素材参考](asset-sources.md) 中本任务相关部分。无需等待全套文案定稿；先与当前制作方明确需要独立编辑或运动的对象，再复用合适已有材料，新增素材以符合场景的网站检索为主，其他途径按主规则补充。将实际可见内容、适用裁切和缺少的关系反馈给 A/主代理，共同调整图文。交出真实可用的项目内素材文件、构图/图层和必要来源或提示词；替图保留必要关系。生图风格服从模板或已确定的视觉方向，背景图不能烘焙必须独立编辑或运动的对象。B 不改权威 PPTX。

**C：制作与动态。** 读取统一页级安排、模板或视觉方向、所用素材，以及 [制作参考](implementation-and-checks.md) 中相关章节。尽早核实工具能力，并与 B 约定分层、运动参照和需要的真实状态。负责授权范围内的实际页面、原生对象与动态，完成 [最小制作核对](implementation-and-checks.md#minimum-production-confirmation)，不只回交分镜建议。布局适应内容，不能为凑行数把已写清的句子压缩成生硬标题；有实质改写时回交主代理统一。先按 [信息关系选择效果](implementation-and-checks.md#choose-the-effect-from-the-explanation)，需要具体示范时再读对应案例。完成时交权威 PPTX 路径、约定源文件、实际实现内容和具体受限项。

委派消息应包含角色、具体页面/问题、必要原材料与模板路径、共享约束、应读章节、输出形式/路径和允许写入的文件。传递完成该工作所需的上下文，不将全部聊天和所有参考无差别复制给每个角色；当前约束和原材料定位必须充分。

## Sequence and file ownership

1. 主代理确定需求、初步讲解依赖和全局约束。A 整理初稿时，B 可盘点、寻找和检查实际素材，C 确认工具与对象实现方式，并向 B 提出图层和运动参照需求；依赖尚未明确的页面不提前固化内容或动画。
2. 主代理汇合来源与素材的实际内容，A/B 共同修订受影响的文案、视觉和分层，C 接收依赖已明确的页开始制作。按页往返推进，不必等待全套素材准备结束，也不能拿尚未确认的内容制作成稿。
3. **启用 C 时由 C 独占权威 PPTX 及其制作脚本写入；未启用 C 时由主代理写。** A/B 只写分配的内容或素材文件，其他代理不覆盖共享笔记或权威稿。复用已有项目目录；不要求建立 A/B/C 文件夹或多套最终稿。
4. 主代理收到新修改时，先更新给当前写入方，让其串行完成；需要接手时，先等待当前保存完成并停止后续写入，回交最新保存路径和未完成项，再明确转移写入权。后续来信与局部修改也沿用这一规则；不能主代理与 C 同时保存同一文件，也不在保存中途强行接管。
5. 主代理处理交接中的实际缺口、更新依赖项并交付一个权威最新版。角色自报完成、动画脚本运行或文件存在不能被改写成已经渲染、播放或人工验收。

## Changes and blocked work

专项发现需要改变页数、讲解顺序、证据含义、模板或编辑粒度时，回交“问题、受影响页、建议”；主代理在已授权范围内决定并更新后续输入。只有真正超出授权或无法合理解决的关键缺口才询问用户，内部交接不变成新的审批关卡。

失败回交具体操作、原因/错误、仍可用的成果路径、受阻页面和恢复所需条件；继续独立工作，不做无依据的相同重试。不得用生成图补真实截图/数据、将静态稿称为动态、以视频替代要求的原生编辑，或因代理不可用就放弃可完成的制作。

对应角色完成各自的素材、来源、文案和对象写入核对；当前 PPTX 写入方确认保存结果及受影响页面的必要渲染与动态效果检查，未完成项按实际原因交接。协作不改变已约定的交付/检查方式，也不因专项发现问题就扩大修改范围。

## Handoff examples

**局部替图。** 用户要求“把第 5 页换为提供的新截图，保留文字与动画，我自己检查”。主代理可直接读取目标页和新图，保留对象及其效果目标，替换并保存原权威稿；无需启动 A/B/C、重新选风格、搜索额外素材或播放整套 PPT。

**两个专项。** 用户已确认完整文案和真实数据，要求重做场景素材及复杂原生动态。主代理保留内容口径，B 准备场景图、图层与分镜，C 确认接口并独占 PPTX/脚本制作；主代理承担必要的来源和文案衔接，不为了凑齐角色另启 A。

**内容、素材与动态结合的重做。** 用户提供产品说明、操作记录和培训模板，要求讲清组成、使用步骤与操作前后状态：

| 交接 | 示例内容 |
| --- | --- |
| 主代理 → A | 需要讲清的听众目标、来源文件定位、页数与拟定页关系；请给可见解释、证据位置及事实状态。 |
| 主代理 → B/C，独立准备 | B 先读取模板和现有素材；C 先读取原模板与现有制作脚本，确认可用的原生对象和效果接口。 |
| A/B → 主代理 → C | A 从说明和记录写初稿，B 检查真实图像与可见状态；共同纠正文案和素材不对应之处，明确哪些结构有来源、哪些状态只能示意。主代理统一页内容和当前顺序。 |
| B → 主代理/C | 状态页沿用实际截图；组成页按已确认的关系保留原生部件和连接，所用图像保存到项目素材目录并附来源；给出入场、操作后状态与固定参照。 |
| C → 主代理 | 权威 PPTX 的实际路径、写入的对象效果、已完成的必要检查和仍影响使用的具体问题；不附“播放通过”等未执行结论。主代理处理实际缺口后直接交付，不另增审批。 |

以上是交接写法示例，不代表已有文件或运行结果。页数、示例内容和启动角色均服从实际任务。
