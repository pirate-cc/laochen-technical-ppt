# Explanation and Chinese copy

本文件负责讲解顺序、可见文案和图文对应。按任务选读；局部修订只处理受影响的含义及必要上下文，审阅按 [任务范围](../SKILL.md#task-scope) 报告。素材获取见 [素材参考](asset-sources.md)，动态实现与检查见 [制作参考](implementation-and-checks.md)。

选读：[场景与讲解](#choose-the-explanation-from-the-scene)、[页面角色](#substance-by-page-role)、[图文调整](#copy-and-asset-iteration)、[来源写作](#writing-from-sources)、[辅助文字](#audience-facing-qualifications-and-small-text)、[自然中文](#natural-chinese-technical-copy)。

## Choose the explanation from the scene

先从请求和资料判断：讲什么、给谁看、希望观众理解或完成什么、现场讲演还是独立阅读。已有上下文足够时直接选择；只澄清会实质改变内容的缺口。根据所需知识和信息依赖安排顺序，再分配各页内容。题材名称不能单独决定大纲，同一主题也可能用于认识、操作、比较、决策或叙事。

| 本次目的 | 组织讲解的依据 | 页面应提供什么 |
| --- | --- | --- |
| 认识对象、作品、产品或概念 | 观众首先需要知道的身份、特征及其关系 | 清楚的整体、可辨认的特征，以及这些特征怎样对应说明；按需解释术语。 |
| 学会操作或完成任务 | 实际前置条件、操作顺序、反馈与结束状态 | 在何处做什么、操作后看到什么；只在必要位置介绍例外或判断。 |
| 理解组成、过程或机制 | 组件连接、输入输出、因果、位置或运动关系 | 整体关系与关键细节，必要时用公式、状态或中间步骤解释。 |
| 比较变化、结果或方案 | 可比对象、共同条件、重要差异 | 对齐的材料和有依据的解释；涉及判断时说明实际采用的标准。 |
| 理解人物、历史、经历或发展 | 时间、空间、人物行动、作品或事件之间的联系 | 可定位的事实与材料，适合主题的叙事线索；不强套输入输出链。 |
| 作出选择、讨论取舍或推进工作 | 当前问题、证据、可行选项及其影响 | 支持当前决策的依据和取舍；有需要时给行动或讨论题。 |

按实际材料选择或组合这些组织方式，不把表格变成固定页面清单。定义或整体关系应先于依赖它的细节，但已具备相关知识的听众不必重听基础介绍。讲述顺序可以不同于事物发生或计算的顺序；展开具体过程时仍须保持其真实关系。

## From observation to method

“原始记录 → 观察现象 → 处理需求 → 方法选择 → 输出解释 → 总结”适合由观测驱动的方法汇报，是一种可选依赖关系。作品介绍可以沿对象与细节展开，操作培训可以沿任务与反馈展开，决策报告可以从问题与选项展开。先选择适合本次目的的顺序，随后在约定页数和时长内合并或展开内容。

## Let the materials set the scope

围绕资料能直接支持的对象、结构、机制、操作或现象写出完整解释。介绍自然结束时即可收住；只有任务涉及评价、计划或决策时，才展开相应结果、验证或下一步。实际比较中的条件、不确定性和结果状态属于含义的一部分，不能删除。

同一资料可以承担不同用途：照片可解释可见外观，带位置依据的平面图可解释布局，数据可说明比较。材料不能支持的关系，改用合适来源或调整解释范围；不要从单张照片推导不可见布局，也不要从相关变化直接写成因果。

## Substance by page role

| 页面承担的作用 | 可直接使用的内容应包括 | 常见修订方向 |
| --- | --- | --- |
| 对象或概念介绍 | 它是什么，哪些特征或关系值得理解 | 将抽象评价替换为具体特征，必要时用图中实例解释术语。 |
| 方法或机制 | 关键操作及其输入、变化和输出含义 | 将过程名称展开为实际做法，选择有解释力的公式、状态或算例。 |
| 操作培训 | 操作对象、动作、可观察反馈或结束条件 | 把“完成配置”等标签改为具体操作及结果；说明随对应控件出现。 |
| 系统或空间关系 | 组件的作用、相互连接或相对位置 | 从名词列表转为对象之间的合作、传递或布局。 |
| 比较或结果 | 比较对象、共同口径、来源支持的差异及意义 | 对齐条件、单位与时间；使用实际计算，不补造原因或最优结论。 |
| 叙事或作品解读 | 可定位的事件、作品或观察，以及它们之间的联系 | 用具体材料支撑讲述，区分记录、引用、解释和推断。 |
| 选择或计划 | 目标、依据、选项或具体操作 | 写清实际取舍或安排；仅在任务需要时加入。 |

一页可以结合若干方面，但应形成连贯意思。完整解释可以很短；不要求固定四框、固定字数或每页都包含结论与计划。

## Figure and adjacent explanation

先明确图像在本页的作用，再写图旁说明。解释性图像应能让观众定位正文所说的对象或关系；情境和氛围图可以建立场景，但不承担事实证明。

- 对照片、作品和产品图，说明实际可见的特征、局部和构图关系；不添加画面没有的部件或事实。
- 对截图，解释实际控件、状态、标记或输出，保留影响理解的上下文。
- 对数据图，指出可定位的趋势、差异或范围，保留单位、条件和数据口径。
- 对流程、结构或地图，说明节点作用、连接、方向和空间关系，使文字靠近相应对象。

问题可以引导讨论，但不能成为图旁唯一内容。标题、说明和主图应共同完成本页任务。复杂材料可用整体加局部放大；必要的坐标、标注和比较对象保持可读。

## Locating evidence during explanation

| 需要定位的对象 | 可选标识 | 必须保留的内容 |
| --- | --- | --- |
| 点、部件、控件或局部特征 | 短引线、箭头或直接标签 | 被指对象与必要标签；引线经过空白区域。 |
| 时间范围或空间区域 | 轮廓框、浅色区间带 | 原始细节、坐标，以及来源定义的边界含义。 |
| 一组对象或相邻面板 | 括号、侧标、关联轮廓 | 组内身份和比较关系。 |
| 在展示尺寸下过小的细节 | 与原区域关联的局部放大 | 来源身份、位置、单位和尺度变化。 |

标识位置来自实际图像或数据。讲演中让标识和对应说明一起出现，保留比较所需的上下文；阶段与效果按 [动态规则](implementation-and-checks.md#progressive-explanation-and-animation) 确定。阅读版可采用完整的静态标注状态。

## Explain the method in the project

需要讲解方法时，按实际内容说明输入、关键操作、输出含义，以及它在项目或来源中的作用。这些是解释的方面，不是必须填满的四个框。“拟合直线并逐点相减”说明了操作，“处理：预处理”只重复类别。

连接各步骤实际传递的数量或对象。文献介绍沿来源的方法解释，项目实现依据实际代码与记录；不把文献性能写成项目性能。完整的自包含算例见 [方法单页](worked-examples.md#complete-one-slide-rewrite)。

## Concept comparisons

比较维度由观众目的和实际材料决定。可以比较属性、用途、过程、条件或结果；选择足以解释差别的依据，不为凑维度补内容。区分直接观察和进一步解释，避免仅把两组名词排成表格。

## Cumulative method chain

对于有依据的“输入 → 操作 A → 中间状态 → 操作 B → 输出”，先让观众认识输入，再逐步介绍相关操作与状态。中间状态是否单独讲解，取决于理解需要。具体的入场、箭头、动作和保留上下文统一按 [动态实现](implementation-and-checks.md#progressive-explanation-and-animation) 安排；不把一个例子的点击数量推广到其他场景。

## Copy and asset iteration

新建或实质重做时，先写本页要表达的意思和初稿，并确定需要的视觉证据、构图与运动对象。素材尚未确定的细节暂留为内部问题，不写成事实。取得实际素材后，核对对象、可见特征、方向、时间、单位和图层，再共同确定可见文案与分镜。

- 素材支持解释且质量合适：使用准确、具体的名称和图中对象完成成稿。
- 素材只支持部分解释：补充适当材料、调整受影响的文案，或选择更合适的视觉形式。
- 表达的是既定事实，但选图不能说明它：更换素材或保留可靠图解；不能为了迁就图片改写事实。
- 定稿后的布局暴露拥挤或图文脱节：先调整构图与必要文案，再考虑字号；保留已确认的技术含义。

局部任务只在其范围及必要依赖内往返调整。可直接完成的页面继续推进；不为每次调整增加用户审批，也不因一页缺图重写全稿。定稿时连同相邻页通读，确认前后衔接。

## Writing from sources

- 来源给出事实、数据、图像或原话；写作把它们组织成适合本次听众的解释。保留能够定位的出处，区分原作者的结论、项目记录、教学构造和推断。
- 标题可直接命名对象、操作、比较问题或有依据的结论；按页面目的选择，不强制所有页面都写结论句。
- 正文说明具体对象的含义、做法、关系或现象。必要时读原始公式、资料、代码或图注；不从一句摘要扩写出未经来源支持的细节。
- 相邻页通过对象、概念、时间、数据交接或实际结果衔接。同一案例可重复使用，只要每页增加不同解释。
- 项目进展说明有记录的工作和所得，文献与作品内容归于实际来源。一次删页、固定标题或改顺序只属于当前任务。

## Audience-facing qualifications and small text

可见文字用于解释主题。标题后优先接有实质的内容，不例行添加“本页主要介绍……”、小号灰色讲述提示或重复总结。副标题在提供必要范围、条件、定义或发现时保留；有用的口头过渡可放备注。

| 信息 | 放置原则 |
| --- | --- |
| 对象名称、变量、单位、定义及解释所需条件 | 可读标题、图注或邻近说明；与对象同步出现。 |
| 实际比较的样本、口径、不确定性或结果状态 | 放在相应比较附近，保持来源含义。 |
| 不改变理解的详细出处、生成方式和制作记录 | 来源信息默认放备注；必须可见的署名或披露按实际要求保留。制作过程信息放内部记录或必要的交付说明。 |
| 讲述节奏和补充例子 | 按需放备注，可见正文仍须能说明主题。 |

删去泛化提醒时保留图旁解释、标签、单位和必要署名；不通过放大、改色或改名为“图注”保留冗余句。用“概念场景示意”“教学算例”“仿真结果”等准确名称表达素材身份，具体技术信息随对象可见。

介绍页无需自动附“当前没有……”“尚未验证”等缺陷声明；实际结果中的不确定性和比较基础仍要保留。阅读稿需要足够的可见解释，讲演稿的备注可支持节奏，按 [讲演与阅读示例](worked-examples.md#live-and-reading-versions) 处理；不要求每页都有逐字讲稿。

## Natural Chinese technical copy

- 交付可直接上屏和讲解的文字。围绕具体对象写清所需的含义、做法、关系或现象；正文不能只给概念标签或等用户扩写的提纲。备注补充例子与节奏，可见文字本身应清楚。
- 使用自然、准确的中文，专业程度适合听众。检查主语指向、动宾搭配和因果关系；抽象词连续出现时回到实际对象与操作。保留确有含义的词，不建立机械禁词表。例如把“以结构统合多元功能”改为实际部件怎样连接、分别完成什么。
- 必要术语保留，并用本次对象、操作或图像解释。熟悉题材的听众可直接使用共有概念；初学者需要具体例子。自然表达不降低事实和技术准确性。
- 不为对仗、四字短语、字数、行数或卡片数量增删含义，不补造第三项凑列表。保留真实并列与正常对齐，不把全部标题改成同一种句式。
- 在授权写作范围内连同标题、小标题、正文与图注通读：是否顺口，指代是否明确，标题是否由正文和图片支撑。修订受影响的生硬搭配、抽象堆叠和重复句框；只读审阅报告发现与建议。
- 内容有实质与表达自然同时满足。去掉空话后保留或补足相关知识；有知识但不好读时改写表达。不要把必要解释全部挪进备注，或把冗余句变成更大的强调文字。见 [中文改写示例](worked-examples.md#natural-chinese)。
- 文字排得下与文字写得好分别处理。中文混排、字体、标点、单位、符号与换行按 [制作与文本适配](implementation-and-checks.md#chinese-text-fitting-and-fonts) 执行。

### Titles and cover copy

封面先说明人物、作品、产品、项目或课程主题，副标题按需补充范围与角度。用户要求的叙事或艺术风格可以保留，同时让主题清楚。页标题采用本页最自然的对象、操作、问题或有据结论；不强制冒号、对仗、结论句或固定长度。小标题帮助辨认内容，需要展开的概念放正文解释。
